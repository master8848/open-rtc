# Transport — signaling and horizontal scale

Current behavior for `packages/transport/src/*`, `packages/server/src/relays/*`, `packages/server/src/stores/*`, `packages/server/src/ws.ts`.

`SignalingTransport` contract is `join(roomId,self)/leave/emit(envelope)/onMessage/onPresence/setPresence/dispose` with `TransportMetadata name/ordering/maxPayloadBytes` (`packages/transport/src/types.ts:44`, `packages/server/src/services.ts`). `Room` accepts `transport: SignalingTransport | SignalingTransport[]` where array sugar builds `CompositeTransport` (`packages/transport/src/composite.ts`).

Client resilience: `CompositeTransport` (`packages/transport/src/composite.ts:25`) emits via `primary` then `fallback` on error and dedupes `onMessage` by `sessionId:seq` via `OrderedMessageBuffer` (`packages/transport/src/internal/reorder.ts:30`); `ReconnectingTransport` (`packages/transport/src/reconnecting.ts`) retries with exponential backoff, re-joins and replays via `listSignalsSince(lastSeq)` and emits `connection-state: reconnecting|reconnected|failed`; `IceCoalescer` (`packages/transport/src/internal/iceCoalescer.ts`) batches trickle candidates `coalesceIceMs 50-100ms` before `emit`; `WebTransportSignalingTransport` (`packages/transport/src/web-transport.ts`) is unordered datagrams with WS fallback. `RoomConfig.reconnect` delegates to `ReconnectingTransport` without `Room` changes.

Relay: `Relay` (`packages/server/src/services.ts:22`) is `attach(roomId,socket,senderId,sessionId)/detach/broadcast(roomId,envelope,{exceptSenderId})/clientCount`. Default `RoomHub` (`packages/server/src/ws.ts:59`) is `Map<room,Set<Socket>>` with `WeakMap` meta; pluggable `RedisRelay` (`packages/server/src/relays/redis-relay.ts:45`) publishes to `vidcall:room:{roomId}` via `pub/sub` `ioredis`/`redis` peer dep and fans out to local `RoomHub`, subscribing per-room on first `attach` and unsubscribing when `clientCount===0`; `PostgresNotifyRelay` (`packages/server/src/relays/postgres-notify-relay.ts`) uses one dedicated `pg.Client` `LISTEN`+`NOTIFY` with 7 KB `Chunker` (`packages/transport/src/internal/chunker.ts:53`) reassembly. Wire `attachWebSocketRelay(server, services, { relay })` (`packages/server/src/ws.ts:122`) and set `services.relay = relay` so HTTP `handleSignal` (`packages/server/src/core.ts:269`) calls `relay.broadcast` on every instance.

Store: `Store` contract (`packages/server/src/store.ts:22`) is ~10 methods `getRoom/putRoom/deleteRoom, getParticipant/.../listParticipants, putSignal/listSignals, putRecording/...`. `InMemoryStore` (`packages/server/src/stores/InMemoryStore.ts:14`) is in-process; `PostgresStore`/`MySQLStore`/`SqliteStore` exist and `PostgresStore` holds `pool`+`listenerClient` for `LISTEN`; `RedisStore` (`packages/server/src/stores/RedisStore.ts`) uses `ZSET/XRANGE`+TTL. JS/Bun relay handles 10k msg/s/core; Rust sidecar is deferred until benchmarked need.

Limits: per-backend ceilings (`TransportMetadata.maxPayloadBytes`, `docs/limits.md` table) are WS `8MB` `seq-required` with `IceCoalescer`, Supabase `~256KB` `guaranteed`, Firebase `~256KB`, Convex `~1MB`, Postgres `NOTIFY` `7KB` chunked, SQLite local, Redis `~512MB`, WebTransport `~1-64KB` unordered.

Related: `docs/limits.md` (full matrix, chunker, coalescer), `packages/server/README.md` (Store, relay wiring), `docs/plans/archive/04-transport-signaling-scale.md`.
